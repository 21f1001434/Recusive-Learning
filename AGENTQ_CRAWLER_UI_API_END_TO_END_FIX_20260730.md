# AgentQ Crawler + HIP UI/API Autonomous Mission

## Objective

Complete the full HIP form mission from the current `input.json` through:

1. Data Map
2. Source Document Type
3. Target Document Type
4. Rule
5. Source Transport Profile
6. Target Transport Profile
7. BizFlow

The same authenticated Chrome session is used for UI execution, Playwright MCP evidence, Chrome DevTools MCP evidence, HIP Intelligence MCP planning/critique, Dell AIA text reasoning and Gemma vision verification.

## Dell.com crawler concepts applied

The implementation ports the useful production patterns from the Dell.com crawler into the HIP form domain:

- compact web representation rather than unbounded raw-page prompting;
- deterministic action safety gate before LLM ranking;
- AgentQ actor/critic action scoring;
- UCB-style exploration/exploitation using real trajectory rewards;
- DOM mutation-settle observation before judging an interaction;
- persistent, value-free trajectory memory;
- ReAct observe → classify → plan → act → re-observe → judge recovery;
- frontier-style completion ledger so unresolved phase work cannot be silently skipped.

The LLM cannot invent selectors, JavaScript, endpoints, HTTP methods or payload keys. It selects only among controls and API contracts proven by live browser evidence.

## UI-first parent-child execution

Every phase is compiled into an ordered dependency graph. A child is not filled until its parent is committed, the Angular transition settles, the child mounts and the child is rebound from the fresh DOM. Repeatable rows use an exact transaction barrier:

```text
create row N
→ fill all required row fields
→ verify exact values
→ prove unique physical identity
→ settle DDS/Angular rerender
→ create row N+1
```

## API intelligence and payload extraction

For each phase the agent separates browser traffic into:

- form-open/reference traffic;
- UI-fill/validation traffic;
- exact final Create/Save/Submit traffic.

It exports:

- `form_open_api_contracts.json`
- `ui_fill_api_contracts.json`
- `phase_api_catalog.json`
- `ui_api_input_crosswalk.json`
- `observed_openapi.json`
- `postman_collection.json`
- `shadow_phase_payload.redacted.json`
- `blocked_submit_api_capture.json`
- `agentq_api_action_ranking.json`
- `api_execution_result.json`
- `form_api_agentq_result.json`

Request/response examples are redacted. Shapes, endpoint templates, status codes, stages, initiators and input-to-API key mappings are retained.

## Exact submit capture safety

After the UI form and all judges pass, the agent may press the visible Create/Save/Submit control only while a Playwright route handler is active. Every `POST`, `PUT`, `PATCH` and `DELETE` is aborted before backend delivery. The exact endpoint, headers and request body are captured in process memory; the persisted artifact is redacted.

This provides the real payload generated by the UI without creating an object.

## API execution modes

### `capture` — recommended default

- Fill and verify the UI.
- Capture the exact submit request behind the network-abort barrier.
- Export API contracts, OpenAPI, Postman and crosswalks.
- Do not send an API mutation.

### `dry_run`

Same backend safety as capture, with an explicit dry-run result.

### `validate`

Uses the validation requests and responses already observed during the UI transaction as validation evidence. It never sends a redacted or reconstructed request.

### `write`

Replays the exact request captured in memory through the authenticated `BrowserContext.request` API context. It requires both:

```text
--allow-api-mutation
HIP_ALLOW_API_MUTATION=YES
```

The exact request body and authorization headers are process-memory-only and are never written to disk or promoted to Portal Brain.

## Deterministic acceleration

After a phase passes exact DOM verification, dependency verification, section judge, text judge, vision judge, golden comparison and API evidence gates, the agent promotes:

- stable semantic selectors;
- framework keys and `formcontrolname` selectors;
- parent-child edges;
- row topology;
- event sequence;
- conditional mount waits;
- rerender/rebind rules;
- API endpoint templates and payload shapes;
- observed success/failure trajectory rewards.

Future runs exploit this path first. Drift returns only the earliest unresolved dependency to exploration.

## Safety

Normal UI execution does not save, create, submit, delete or deploy. Submit-payload capture blocks all mutation requests at the browser network boundary. API write is disabled unless the two independent confirmation keys are present.
